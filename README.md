# Felix Field

Field monitoring web app for Felix, an agricultural extension officer in Kasungu (Malawi). Demo with fictional data.

- **Product & technical spec:** [`spec.md`](spec.md)
- **Database handoff (Azure PostgreSQL):** [`docs/database.md`](docs/database.md)

## Run locally

```bash
npm install
npm run dev          # http://localhost:3000 — uses data/seed.json, no configuration needed
```

| Command | What it does |
|---|---|
| `npm run dev` | Development server (`DATA_SOURCE=memory` by default) |
| `npm run build` | Production build (same as Vercel) |
| `npm test` | Domain logic and seed tests (Vitest) |
| `npm run lint` · `npm run typecheck` | Quality checks — run before every PR |
| `npm run seed:generate` | Regenerates `data/seed.json` and drone images from `scripts/generate-seed.mjs` |

## Field analysis (API pipeline)

Alerts, actions and the weather shown in the app are computed by the external APIs (TypeScript ports of `tools/python/`), not written by hand:

1. `lib/kasungu/db.ts` reads the field db (`data/kasungu/*.csv`).
2. `lib/pipeline/observations.ts` builds each field's context in the `risk.py` format. Field evidence comes from the simulated monitoring layer in `data/seed.json` (soil sensors, drone, monitoring reports, planting), real **OpenWeather** forecasts for the 8 zone stations, an **iSDA** nutrient plan for fields with soil issues, and **crop.health** for uploaded plant photos.
3. `lib/external/risk.ts` is the port of `risk.py`. **Claude** classifies the fields that have evidence into Disease, Fertilizer, Maturity and Urgent flags, with actions.
4. `lib/pipeline/to-seed.ts` and `diff.ts` turn the result back into seed tables. Screens and colour rules stay the same, and a list of what changed is saved with each run.

The pipeline runs by itself the first time the dashboard is opened, then again each time **Update** is pressed. Photos uploaded from a field page wait for the next Update. Every run is saved as a snapshot in Vercel Blob (`BLOB_READ_WRITE_TOKEN`, public store) or, locally without a token, in `.data/`. A source without its key is skipped. If Claude fails, the previous alerts are kept.

## Demo data notes

- "Now" is fixed at **1 March 2027, 07:00 Malawi time** (`DEMO_NOW`), so urgencies don't change with the day of the demo.
- 600 fields in 12 village clusters around Kasungu; ~10% have an issue. KSG-001…020 are the hand-written demo cases.
- Field polygons are placed programmatically; redraw the demo ones on real farmland with [geojson.io](https://geojson.io) (#5).
- Drone pictures in `public/drone/` are generated sample NDVI images, labelled as such.
- Agronomic content is a plausible first draft and must be validated by an agronomist.
